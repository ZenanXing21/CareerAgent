# Career Agent「静谧对话」双端改版设计

## 1. 意图

把当前偏后台工作台的 Career Agent 改造成一个以对话为第一入口的求职助手。首页借鉴豆包桌面版的安静、聚焦和低视觉噪音，同时保留 BOSS/猎聘式求职产品应有的可靠、明确和职业感。

目标用户进入页面后不需要理解复杂工作流，只需要知道一件事：把真实经历告诉 Agent，系统会逐步整理出简历。简历编辑、岗位搜索和定制简历仍然存在，但在需要时才出现。

## 2. 已选方向与备选方向

### 已选：A「静谧对话 · Doubao Calm」

- 桌面端使用 72px 左侧图标栏和居中的对话工作区。
- 手机端使用顶部品牌栏、全屏对话区和底部固定输入框。
- 首屏只突出一个主任务，不同时展示档案完成度、简历缩略图或大段流程说明。
- 整体使用温暖的浅灰白背景、深海军蓝文字和克制的青绿色状态色。

选择原因：最符合用户喜欢的豆包桌面风格，也最适合“不填表、直接聊天生成简历”的产品逻辑。

兼顾聊天、流程和预览，扩展性强，但首页仍有多个视觉焦点，不如 A 简洁。

## 3. 目标

- 桌面和手机都以对话作为第一视觉焦点。
- 保留现有四阶段业务：对话建档、初版简历、发现岗位、定制简历。
- 不改变后端 API、数据模型、模型调用方式和现有业务规则。
- 保留文件上传、对话预览、简历编辑、模板选择、Word/PDF 下载、岗位搜索和投递流程。
- 降低导航、状态信息和说明文字的视觉权重。
- 所有交互同时满足鼠标、键盘和触屏使用。

## 4. 非目标

- 本次不重写后端、不更换前端技术栈、不引入 React/Vue 或构建工具。
- 不修改导出到 Word/PDF 的简历模板视觉系统。
- 不新增账号、云同步、深色模式或新的求职功能。
- 不复制 BOSS、猎聘或豆包的品牌元素、图标和商标，仅借鉴信息层级和交互气质。

## 5. 视觉系统

### 色彩

- 页面背景：`#FAF9F6`，温暖而不发黄。
- 主文字与主按钮：`#14283B`。
- 次级文字：`#667788`。
- 强调色：`#0F8F78`，只用于当前状态、成功和关键焦点。
- 卡片/输入区：`#FFFFFF`。
- 边框：`#DCE4E7`。
- 错误：`#C43D4D`；警告：`#A66A16`。
- 正文对比度至少 4.5:1，状态不能只用颜色表达。

### 字体与间距

- 中文优先使用 `Noto Sans SC`，回退到 `Microsoft YaHei`、`Segoe UI` 和系统无衬线字体。
- 不依赖远程字体加载，保证本地应用离线可用。
- 字号系统：12 / 14 / 16 / 20 / 28 / 36px。
- 使用 4px 基础、8px 主节奏；主要间距为 8 / 16 / 24 / 32 / 48px。
- 对话正文桌面端最大行宽约 70 个字符，手机端保持 35–55 个字符。

### 形状与阴影

- 大容器圆角 18px，输入区 16–18px，普通按钮 10–12px，胶囊按钮 999px。
- 只在输入框、弹层和浮动工具栏使用低透明度阴影。
- 不使用大面积玻璃拟态、强渐变或装饰性动画。

### 图标

- 使用统一的 1.75–2px 线性 SVG 图标风格。
- 不使用 Emoji 作为导航或系统图标。
- 图标按钮最小可点击区域 44×44px，并提供 `aria-label` 和桌面端 tooltip。

## 6. 全局布局与导航

### 启动与状态恢复

- 新候选人或尚未生成初版简历的候选人进入对话建档页。
- 已生成初版简历的回访用户继续沿用当前行为，恢复到初版简历页，不强制退回对话首页。
- 已确认简历但正在后续流程的用户恢复现有数据和已解锁导航；当前 POC 不新增跨重启的“最后页面”字段。
- “对话是第一入口”指新建档流程的产品入口，不覆盖已完成阶段的状态恢复。

### 桌面端（≥ 1024px）

- 左侧保留 72px 固定图标栏，替换当前 258px 文字侧栏。
- 图标依次对应：对话建档、初版简历、发现岗位、定制简历。
- 当前步骤用浅青绿色底色与深色图标表示；未开放步骤保持禁用语义和较低透明度。
- hover 或键盘聚焦时显示文字 tooltip，避免纯图标导航不可理解。
- 顶部栏高度约 56px，仅显示当前区域名称和系统状态；不再出现占空间的大标题。
- 主内容占满剩余高度，各页面按内容类型设置自己的最大宽度。

### 手机端（≤ 760px）

- 不显示左侧图标栏。
- 顶部固定品牌栏，高度 56px，右侧为 44×44px 菜单按钮。
- 菜单按钮打开右侧或底部导航 sheet，显示四个带图标和文字的阶段以及当前状态。
- sheet 可通过关闭按钮和 Escape 退出，不依赖滑动手势。
- 底部输入框必须为页面内容预留安全区域，不能遮挡最后一条消息。

### 中间尺寸（761–1023px）

- 使用 64px 图标栏。
- 编辑器和岗位详情从双栏降为单栏。

## 7. 对话建档页

### 初始状态

- 桌面端内容区最大宽度 760px，垂直居中偏上。
- 展示 AI 标识、标题“今天想从哪里开始？”和一句短说明。
- 快捷操作为“从零生成简历”“优化已有简历”“上传简历或照片”。
- 输入框固定在对话工作区底部，不再包在大型白色面板中。
- 当前冗长欢迎语改为两层渐进披露：首屏短说明；用户开始后由 Agent 在对话中说明缺失项。

### 进入对话后

- 首屏欢迎区平滑收起，对话列表取得主体空间。
- 消息最大宽度桌面 76%、手机 88%。用户消息深蓝底，Agent 消息浅灰底。
- 收集摘要默认折叠为“已整理 N 项资料”状态条，需要时展开，不持续占据大面积空间。
- 上传队列显示文件名、类型状态和明确的移除按钮。
- 生成的简历预览作为对话中的宽卡片出现，可展开查看，不把用户强制导航到下一页。
- “进入初版简历精修”只在预览成功后作为唯一主按钮出现。

### 输入框

- 桌面端三列结构：附件按钮、自动增长 textarea、发送按钮。
- 手机端保持相同横向结构，不再把发送按钮单独换到下一行。
- Enter 发送、Shift+Enter 换行的现有行为保持不变。
- 请求进行中禁用重复发送，按钮显示明确进度，超过 300ms 展示轻量加载反馈。

## 8. 后续页面适配

### 初版简历

- 延续相同全局图标栏和顶部栏。
- 桌面端保留模板设置区 + A4 编辑画布；工具栏更轻，下载和确认为主要操作。
- 手机端不缩放成难以阅读的整张 A4。默认显示可编辑的响应式简历内容流，并提供“页面预览”切换查看真实 A4 效果。
- 响应式内容流是手机端唯一编辑入口；A4 页面预览只读。两种视图读取同一份简历状态，保存后重新渲染预览，不维护两套可编辑 DOM。
- 模块拖拽保留，同时提供上移/下移按钮作为键盘和触屏替代操作。

### 发现岗位

- 桌面端继续使用岗位列表 + 详情双栏，但弱化卡片阴影、统一圆角和标签样式。
- 筛选条件收进紧凑搜索栏和“更多筛选”抽屉，避免顶部表单占据过多空间。
- 手机端为单列岗位卡片；点击后进入全屏详情视图，有明确返回按钮并保留列表滚动位置。

### 定制简历

- 岗位摘要和主要操作置于顶部轻量工具栏。
- 定制简历为主内容；匹配度、建议与事实校验作为可展开的次级区域。
- 手机端按“定制简历 → 匹配分析 → 事实校验”的优先级纵向排列。

## 9. 状态与反馈

- 全局系统状态不再使用醒目的胶囊提示；正常时只显示小绿点和简短文字。
- 错误信息说明原因和恢复方式，紧邻相关区域，并通过 `role="alert"` 通知辅助技术。
- Toast 保留，但不能代替需要用户处理的行内错误。
- 加载时间超过 1 秒时使用内容骨架或分阶段进度文案，避免只有全屏旋转遮罩。
- 动画为 150–250ms，只使用 opacity/transform，并支持 `prefers-reduced-motion`。

## 10. 技术约束与实施范围

- 继续使用现有 `index.html`、`styles.css` 和 `app.js`。
- 尽量保留现有 DOM `id`、`data-view` 和事件绑定，避免功能回归。
- 允许调整语义容器、增加 SVG 图标、增加导航 sheet、折叠区和移动端专用控件。
- 使用 CSS 自定义属性形成语义色、间距、圆角、阴影和动画 token。
- 不增加外部 CDN 或运行时依赖。

## 11. 验收标准

- 1440px 桌面端首屏与所选 A 稿保持同一结构和视觉气质。
- 在 1024px、768px、414px、375px 和 320px 下无横向页面滚动。
- 手机端正文至少 16px，所有主要点击目标至少 44×44px。
- 四个阶段的原有业务功能和 API 调用保持可用。
- 键盘可访问导航、附件、快捷提示、发送、下载和确认按钮。
- 焦点环清晰，文本满足 WCAG AA 对比度。
- `prefers-reduced-motion` 下关闭非必要动画。
- 页面刷新后仍能恢复现有候选人状态；本次改版不引入新的状态格式。
- 通过现有 Python 测试、JavaScript 语法检查，并增加关键 DOM/响应式结构的回归验证。

## 12. 留给实施者的普通决策

- 具体 SVG path、局部 1–2px 间距和阴影数值可在不改变整体气质的情况下微调。
- 可根据现有 DOM 结构选择 CSS Grid 或 Flexbox，但不得引入布局框架。
- 手机导航 sheet 可从右侧进入或从底部进入，以实际 375px 测试中更稳定的方案为准。

## 13. 用户后续确认的调整（2026-10-27）

以下要求覆盖上文关于固定宽高的初版对话容器及强制必填的规定：

- 对话页以 ChatGPT 式右侧完整工作区承载内容，使用整个可用高度，消息滚动条位于工作区最右侧；正文列最大宽度增至 1000px。
- 聊天开始后保留欢迎区。输入框贴近底部，并在聊天态改为紧凑横向排列。
- 已整理资料默认折叠；用户继续发送消息时收起展开的摘要，避免持续占据阅读空间。
- 基础信息默认继续收集，但用户明确不愿提供的字段必须记为略过，不重复追问，不编造到简历中，也不阻塞生成、确认或导出。后来主动补充该字段时可恢复。
